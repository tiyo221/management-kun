# questions — わからないこと（個人学習バックログ）（モジュール個別仕様）

統合上の位置づけ・共通マスタとの関係・固有データの所在を定める。共通の取り決め（アーキテクチャ・データ規格・名寄せ・デザイン）は [`spec.md`](../../spec.md)（共通仕様）を正とする。

- localStorage: `mk:module:questions:v1`
- ゾーン: **自分**
- 新規モジュール（旧ツールなし。「モジュールを増やして育てる」思想の実践第1弾。Issue #32）

## 役割
自分の「わからないこと」を可視化し、`未解決 → 調査中 → 解決` のループで潰していく個人向けの学習バックログ。skills（ピープル＝他人の能力の可視化）とは役割が異なり、自分ゾーンに置く。

削除は確認を出さず即実行し、`MK.ui.undoDeleteToast` で取り消せる（CONVENTIONS §2.5-3）。`removeItem` は**削除できたかを返す**（その id が無ければ `false`）ので、view は空振りではトーストを出さない。

このモジュールは**2つの独立した軸**で捉える（Issue #81）。両者を1本に潰さないことが肝心:

- **解決したか**（理解の到達点）: `open`（未解決）→ `investigating`（調査中）→ `resolved`（わかった）。
- **ナレッジ化したか**（後で引ける形で書き留めたか）: `resolvedNote`（答え）の有無。

この2軸から3つの居場所ができる:

- **未解決 / 調査中** ＝ バックログ（片づけるもの）。
- **わかった** ＝ 解決した全部。達成ログ／自分が理解したことの記録として**集約する**。うち答え未記入のものは「キャプチャ待ちの学び」。
- **ナレッジ** ＝ 「わかった」のうち後で読める答えを残した部分集合。貯めて何度も引く資産。

**解決（＝わかった）に答えは要らない**（いま解決マークだけ付け、書くのは後でよい）。ただし**ナレッジになるには答えが要る**——答えのないものはナレッジになり得ない。つまり答え必須は「解決の入口」ではなく「ナレッジ化のゲート（`isKnowledge` の定義）」に置く。未記入は「わかった」ビューで可視化・催促して資産化を促す。

## 主操作
**ステータスを次へ送る（未解決 → 調査中 → わかった）**（CONVENTIONS §2.5-1）。一覧の各行に置いたステータス select を1アクション（開いて選ぶ）で切り替えて完了する。モーダルを挟まない。捕捉（Enter で未解決へ追加）→調査→解決、が日々の流れであり、この送りが最も多く繰り返される。付随して、タイトルは行内で直接編集し（インライン・§2.5-2）、背景メモ・タグ・答えは「編集」モーダルでまとめて編集する。答えを書かせる「解決」だけは専用モーダルを残す（ナレッジ化の導線であり、単なるステータス変更ではないため）。ステータス変更で行がタブから外れたら、その行だけ取り除いて件数バッジと「わかった」タブの見出し（`ナレッジ化 N / M`）を更新する（全再描画しない・§2.5-4）。**行を作り直すのは描き方の種類が変わるときだけ** ── 答えのある項目を `resolved` にすると `itemRow` はナレッジカードを返す（別レイアウト）。同じレイアウト間の遷移（未解決⇄調査中など）で毎回作り直すと、操作中の select ごと DOM から外れてフォーカスが飛び、キーボードで選び続けられなくなる（[`spec.md`](../../spec.md) §10.2）。作り直すときは新しい行の先頭コントロールへフォーカスを戻す。

ナレッジカードも質問文はインライン編集し、モーダルは「編集」ボタンから開く（同じ一覧に2種類の操作方法を混ぜない）。ただし**答え本文はカード上で編集しない**（複数行で、カードの主役が入力欄になると読む面でなくなる）。**ステータス select も置かない**（ナレッジは読むための面で、格下げは稀。必要ならモーダルから変える）。

## 共通マスタ関係
People / Project マスタは**使わない**（todo と同じく個人用途）。`tags` は自由文字列で、将来 Tech Radar 等と接続する布石とする（現状は名寄せしない）。

## 固有データ
- `items[]`: `{ id, title, detail, status, tags[], resolvedNote, createdAt, updatedAt, resolvedAt }`。`mk:module:questions:v1`。
  - `status` = `open`（未解決）/ `investigating`（調査中）/ `resolved`（わかった）。
  - `resolvedAt` は `resolved` 化時に設定、`resolved` から戻すと `null`。
  - `resolvedNote`（解決内容／回答）は任意テキスト。未設定（旧データ）でも壊れない（検索・表示とも空扱い。[`spec.md`](../../spec.md) §4.5 後方互換。追加専用フィールドのため version は据え置き）。
- モジュール内部 ID は `q_<epoch>_<rand>`（[`spec.md`](../../spec.md) §4.7）。

## ナレッジの定義
- **ナレッジ ＝ `status === "resolved"` かつ `resolvedNote`（答え）が非空**。判定は `isKnowledge(it)`。
- 答え未記入の resolved（＝キャプチャ待ちの「わかった」）はナレッジではないが、**「わかった」ビューには集約されて見える**（達成ログの一部・棄てない）。ナレッジ棚（ナレッジタブ）にだけ出さない＝棚の純度は保つ。
- `counts().knowledge` はナレッジ件数（答えありの resolved）。`counts().resolved` は「わかった」全件。`knowledge(search)` はナレッジだけをキーワード絞り込みして返す純関数。

## ビュー・導線
- **ステータスタブ**は 全て / 未解決 / 調査中 / **わかった** / **ナレッジ**。
  - **わかった** ＝ 解決した全部（達成ログ）。先頭に「ナレッジ化 M / N」を出して2軸を可視化する。答え未記入の行は「答えを書く」導線を出し、キャプチャを催促する。
  - **ナレッジ** ＝ 答えありの解決済みのみを **Q→A カード**で表示する（取り消し線は使わない。線は「片づけたタスク」の作法でありナレッジには合わない）。
- **検索対象**はタイトル・詳細・タグに加え `resolvedNote`（答え）も含む。答え本文のキーワードからナレッジを引ける（`filtered()` / ナレッジ専用の `knowledge(search)`）。
- **グローバル検索（コマンドパレット）**はバックログ（未解決・調査中）＋ナレッジを候補にする（`searchItems()`。#81 の再利用導線）。答え未記入の「わかった」は除外する。ナレッジは `sub="ナレッジ"`・`keywords` に答え本文を含める。
- **解決の主導線**: 未解決／調査中の行の「解決」ボタン → 「解決する」モーダル。**答えは任意**（`resolve(id, note)` で `resolved` 化・`resolvedAt` 設定）。
  - 答えを書いた → 即ナレッジ化し「ナレッジ」タブへ遷移。
  - 空のまま解決 → キャプチャ待ちの「わかった」として「わかった」タブへ遷移。あとで「答えを書く」で昇格できる。

## CSV
共通契約（[`spec/import-migration.md`](../import-migration.md) §4.6.2）に沿う。列は `タイトル, 詳細, ステータス, タグ, わかったこと`。

- `タイトル` は必須（空の行はスキップ・件数警告）。
- `ステータス` は key（`open` / `investigating` / `resolved`）または日本語ラベル（未解決 / 調査中 / わかった）を寛容解釈する。不明・空は `open`。
- `タグ` は空白またはカンマ区切り（techstack と同形）。
- 取込は全置換。`createdAt` / `updatedAt` は取込時刻で再生成し、`resolvedAt` は `resolved` のとき取込時刻・それ以外は `null`。
- ラウンドトリップ（出力→取込）が成立する（UTF-8 BOM・ステータス key/ラベル両対応・タグ分割）。

## 旧データ移行
なし（新規モジュール）。

## サマリー（HOME 表示）
`summary(today?)` は `未解決 N件`（残っている学習バックログ）を返す純関数（[`spec.md`](../../spec.md) §3.6）。throughput 系の `今週わかった` は stats から撤去した（方針①・Issue #202。集計 `resolvedThisWeek(today?)` 自体は残す）。`attention` として `停滞 M件`（未解決かつ最終更新から `STALE_DAYS`=14 日以上・warn）を申告する（HOME の要対応帯・Issue #102。`staleCount(today?)`）。全体の未解決と長期分の部分集合である停滞は別事実のため二重表示に当たらない（方針③）。

## 任意契約の採否（searchItems / summaryFor）
グローバル検索（[`spec.md`](../../spec.md) §3.5）と人／PJ 詳細の集約（§3.6.1）は任意契約。採否を固着させる（#220）。
- **searchItems**: 実装（上記「ビュー・導線」）。バックログ＋ナレッジを供給し、答え未記入の解決済みは除外する（#81 の再利用導線）。
- **summaryFor**: 見送り。自分ゾーンで人・プロジェクトに紐づかず、集約先（人／PJ 詳細）を持たないため。
